# Цель: распространяемая TUI Design System для iOS 26

**Актуализация 13 октября 2026:** [пользователь вернул работу в Xcode и нативный каталог](native-catalog-focus-2026-10-13.md). Основной результат — SwiftUI-пакет и приложение каталога в iOS Simulator. Развитие веб-интерфейса прекращено, текущие веб-файлы и доказательства сохраняются как история. Старое разрешение на веб-каталог ниже не является разрешением продолжать его развитие.

**Актуализация 9 октября 2026:** [системные компоненты Apple исключены из переноса](system-components-scope-2026-10-09.md). Из 128 сохранённых исходных наборов 16 `system-*` учитываются как `excluded`; текущая цель — полная приёмка 112 остальных наборов. Для системных элементов новые экраны используют нативные API iOS 26 напрямую. Более ранние требования «все 128 complete» ниже отражают прежний объём. Изменения Figma запрещены.

**Предыдущее уточнение объёма от 8 октября 2026:** [явное решение пользователя](prototype-acceptance-scope-2026-10-08.md) исключает VoiceOver, увеличенные accessibility-шрифты и дополнительные режимы доступности. Все 128 наборов, функциональность и адаптивность Figma, обычная визуальная сверка, специфицированные анимации и работа в Simulator остаются обязательными. Сначала читать полную доступную спецификацию, затем изменять компонент. Требования расширенной доступности далее сохранены как история; они не являются условием сдачи текущих прототипов.

**Обновление порядка от 8 октября 2026:** пользователь попросил переиспользовать выполненную работу и идти через инвентаризацию → спецификации → архитектуру → Foundations → первые три базовых компонента. Актуальный порядок — [docs/work-plan.md](../docs/work-plan.md), индекс и спецификации — [docs/README.md](../docs/README.md). Прежний порядок consumer-first ниже сохраняется как контекст; при выборе следующей работы приоритет имеет новое решение. Полная приёмка и пригодность для SwiftUI-прототипов остаются обязательными.

Решение подтверждено пользователем 6 октября 2026: основной результат — самостоятельная библиотека, которую люди подключают в свои приложения, а Codex использует по ссылкам на репозиторий и экран Figma. Этот документ определяет дальнейшую работу и критерии сдачи.

## Что должно получиться

**Подготовить к распространению через GitHub самостоятельный Swift Package TUI для iOS 26: принять все 112 наборов текущей области поставки по Figma и подтвердить, что новый проект может собрать экран из публичных компонентов по инструкциям репозитория.**

Библиотека сохраняет применимые варианты, состояния, токены, ассеты, поведение и доступность. Состояние, данные и маршруты принадлежат приложению. Нативные контейнеры и взаимодействия iOS 26 используются согласно требованиям проекта. Явно помеченные iOS 18 варианты учитываются отдельно как история.

Качество компонентов и пригодность библиотеки для сборки экранов — два обязательных условия сдачи. Один демонстрационный экран не заменяет приёмку всех наборов; 112 готовых превью не заменяют проверку подключения и использования публичного API.

## Состав результата

- Swift Package с публичным API, токенами и ресурсами; приложение подключает его без зависимости от проекта каталога и без копирования реализации.
- Сопоставление Figma → компонент → вариант → параметры API, включая изменённое содержимое экземпляра и владение состоянием. Поиск компонентов из других Figma-файлов использует подтверждённые постоянные ключи, а не совпадение названий.
- Инструкции для разработчиков и Codex: подключение, поиск компонентов, правила композиции, работа с состоянием, проверка результата и явная обработка отсутствующих вариантов. Примеры должны собираться.
- Нативный интерактивный каталог: настоящие компоненты из пакета с выбором вариантов и работающими действиями.
- Независимое приложение-потребитель и проверенный экран по Figma, собранный через публичный API без визуальных обходов и собственных копий ассетов библиотеки.
- Репозиторий, подготовленный к выпуску: воспроизводимые проверки, состав распространяемых ресурсов, требования среды, описание версии и инструкции установки.

7 октября 2026 пользователь добавил веб-каталог iOS-библиотеки: нативные рендеры и записи, переключение вариантов, копирование SwiftUI-кода, спецификация и параметры анимации. Оформление — по указанному референсу demo-stand. Данные берутся из текущего реестра и публичного пакета; отсутствие реализации, рендера или проверки отображается явно. Отдельная библиотека веб-компонентов не входит в задачу. Для сборки и проверки нативного приложения нужна среда разработки Apple; просмотр веб-каталога не требует Xcode.

## Поэтапный порядок работы

1. **Устранить общие препятствия для использования и распространения.** Проверить системную типографику, ресурсную упаковку и публичные зависимости. При изменении общих исходников повторно принять затронутые компоненты. Открытое решение по шрифтам описано ниже; оно не останавливает независимую работу.
2. **Закрыть первый сквозной сценарий.** Закончить зависимости исходного экрана «Зарплатного клуба» и собрать полный экран в независимом потребителе. Проверить поиск вариантов, передаваемое содержимое, состояние, ресурсы, действия и сходство с Figma. Ограничения компонентов исправлять в библиотеке, композицию и маршруты — в приложении.
3. **Принять остальные наборы по зависимостям.** Для каждого набора: полная применимая матрица → спецификация → публичный API → сопоставления → визуальная и поведенческая приёмка → проверка использования. Закрывать найденные расхождения до объявления набора готовым. Независимые наборы продолжать при проблеме в другом компоненте.
4. **Проверить использование без контекста этой переписки.** По файлам репозитория и ссылке на Figma определить компоненты и собрать экран в чистом потребителе. Проверить полноту ключей, параметры, компилируемые примеры и инструкции. Недостающие сведения должны появиться в репозитории, а не оставаться только в чате.
5. **Провести итоговую приёмку и подготовить выпуск.** Подтвердить все 112 наборов текущей поставки, пакет, каталог и независимый потребитель. Подготовить конкретный состав выпуска и затем согласовать GitHub-репозиторий и публикацию. После разрешённой публикации проверить подключение конкретной версии в чистом проекте; локальная зависимость не доказывает удалённую установку.

Единица результата — принятый компонент либо проверенный экран потребителя. Отчёты, число превью и количество прогонов сами по себе не закрывают этап. Успешные проверки повторяются при изменении связанных входных файлов, найденной ошибке или нерешённом риске.

## Текущая точка и ближайший результат

Исторический снимок до решения от 9 октября: 128 наборов; 59 имеют реализацию, 69 — `catalogued`; 3 — `complete`, 56 — `in-progress`. Полные сопоставления заполнены для 11 наборов; индекс постоянных ключей содержит 14 вариантов и пока частичный. Card Large имеет контейнер и семь сопоставленных композиций, включая skeleton; полный набор ещё не принят. Актуальные числа и готовность определяются `component-coverage.json` и `component-verification.json`, а не этим снимком состояния.

Приняты Skeleton, Skeleton/Text и Header Large. Доказательства: `References/Skeleton/system-validation-2026-10-06.md` и `References/HeaderLarge/final-acceptance-2026-10-06.md`. Приёмка Header относится к текущим локальным входным файлам; изменение шрифта потребует её обновления.

Первый экран — `19287:38717` в файле `ekIyFueS1CutzkrG3JtYJq`. Подтверждённые зависимости: Header Large (`42565:305012`), Card Medium (`11335:41574`), Card Large (`42587:291989`), включая footer, и соответствующие варианты кнопки. Основание — постоянные ключи в `References/ConsumerSalary/assembly-findings-2026-10-06.md`.

Ближайший результат: закончить Card Medium по всей применимой матрице и спецификации, затем Card Large и кнопку; собрать и сверить полный экран потребителя. Card Medium реализован по всей матрице и доступен в каталоге; сопоставление, физические действия, отмена, motion с реальным Reduce Motion и использование в отдельном приложении проверены. Его specification, visual и полная accessibility-приёмка ещё не завершены. [Приёмка потребителя Card Medium](References/CardMedium/consumer-acceptance-2026-10-07.md) подтверждает публичный API, состояние, действия и ресурсы. Card Large имеет [контейнер с геометрией 24 вариантов и нативными действиями](References/CardLarge/container-implementation-2026-10-07.md): четыре package-теста и один UI-тест прошли, skeleton сверён с Figma. [Шесть композиций Header/Header Subheader собраны из публичных Header Card и Button](References/CardLarge/header-compositions-2026-10-07.md); их Day/Night рендеры и копируемые примеры проверены. Остальные композиции и семь проверок набора остаются открытыми. Header Card получил публичный API, все девять вариантов и интерактивный каталог: [реализация и актуальные проверки](References/HeaderCard/implementation-review-2026-10-07.md). [Сопоставление и независимая интеграция Header Card приняты](References/HeaderCard/consumer-acceptance-2026-10-07.md). Он остаётся in-progress: полная спецификация, дочерние состояния, доступность и визуальная приёмка открыты. Проверки отдельных компонентов в потребителе не подтверждают соответствие полного экрана Figma.

Требования проверочного сценария сохраняются: точка входа «Зарплатный клуб (Не ЗП клиент)», нативная навигация iOS 26, видео hero с одним полным воспроизведением и удержанием последнего кадра, инструкция только по кнопке «Как перевести зарплату». Это поведение приложения, а не специализированный API универсальных компонентов. После этого продолжается приёмка остальных наборов до всех 112 текущей поставки.

## Решение по типографике от 20 октября 2026

Пользователь выбрал системный SF Pro iOS 26. Пакет больше не поставляет и не регистрирует файлы старого SF Pro; внутренний совместимый адаптер использует UIFont.systemFont. Публичный импорт остаётся TUIDesignSystem, добавлен продукт TUI-SwiftUI.

[Решение](typography-decision-2026-10-20.md), [проверка Foundations и оставшиеся ограничения](References/Foundations/release-2026-10-20.md). Исторические снимки со старым лицом сохраняются как история и требуют повторной приёмки. Отличия версии SF не скрываются под поправками в потребителях.

Пользователь отдельно разрешил создание GitHub-репозитория, коммит и push. Создан приватный [brokenez/TUI-SwiftUI](https://github.com/brokenez/TUI-SwiftUI); факт отправки и проверки фиксируется отдельным отчётом после push. Это промежуточная поставка библиотеки, не приёмка всех 112 наборов.

## Когда задача считается завершённой

- Все 112 наборов текущей поставки имеют актуальный `complete`, полученный генератором из паспортов: полная применимая матрица, спецификация, визуальная сверка, взаимодействия, доступность, анимации и интеграция. Открытые существенные расхождения и устаревшие входные файлы не допускаются.
- Другой проект подключает пакет и его ресурсы без копирования кода; публичные примеры, каталог и потребитель собираются, необходимые взаимодействия проверены.
- Подтверждён путь «репозиторий + экран Figma → поиск вариантов → публичный API → работающий проверенный экран» с инструкциями в репозитории.
- Состав ресурсов и условия их распространения определены; версия и установка документированы. Удалённое подключение проверено после согласованного выпуска.

Публикация — отдельное внешнее действие после подготовки результата и выбора пользователем репозитория. Этот план не разрешает публикацию автоматически и не выдумывает адрес или версию. До неё продолжается вся необходимая локальная работа.
