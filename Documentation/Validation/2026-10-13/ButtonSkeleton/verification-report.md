# Button Skeleton: общий runtime и нативная проверка

Работа начата 13 октября; итоговый разбор доказательств — 15 октября 2026. Используются Swift Package и приложение каталога Xcode. Веб-каталог не разрабатывался и не использовался для проверки. Исходная Figma не изменена.

## Причина и изменение

В `TUIButton` Skeleton был статичной заливкой. Прочитанная связь экземпляра с main component и обе реакции подтверждают обязательный inherited opacity cycle: 1 ↔ 0.5, 1 ms delay + 500 ms на каждом направлении, Bézier (0.2, 0, 0.4, 0.9). [Полный разбор источников](../../../References/Button/2026-10-13/skeleton-inheritance-reading.md) сохранён до фиксации приёмки.

Button повторно использует существующий `TUISkeleton`; размеры получает от фактического контейнера. Добавлен `cornerRadius` с прежним default 4 pt. Для Button используются исходные 16/12/100 pt. Логика движения, токены цвета, состояния и прежний default API общего Skeleton сохранены. Дублирования анимации в Button нет. Остальные режимы доступности не добавлялись и не проверялись.

## Выполненные проверки

- **3 XCTest passed, 0 failed**: все три размера Button Skeleton в Day/Night, 2 keyframe core в обеих темах, 13 текстовых стилей. Точные размеры и цвета проверены в тестах; 23 нативных PNG @3x сохранены в [PackageNative](PackageNative/manifest.json). [Сводка](package-summary.json), [журнал](package-tests.log).
- **1 Swift Testing test passed, 0 failed** отдельным запуском: 396 промежуточных точек двух направлений и обоих начальных keyframe, границы delay/transition/full cycle. [Сводка](source-curve-summary.json), [журнал](source-curve-tests.log). В первом запуске фильтр без `()` не выбрал этот тест; там фактически 3 теста, а не 4. Повторный запуск с точным идентификатором действительно выполнил проверку.
- **2 native UI tests passed, 0 failed**: 48 последовательных кропов живого Button — 8 × 3 размера × 2 темы. Геометрия каждого остаётся неизменной; действие не вызывается при нажатии на Skeleton. Дополнительно исходный маршрут общего core/Text продолжает пульсировать в активной сцене. [Сводка](native-ui-summary.json), [журнал](native-ui.log), [вложения](NativeUI/manifest.json), [измерения](native-ui-measurements.json). Устройство: iPhone 17 Pro, 402 × 874 pt @3x, iOS 26.4.1 / 23E254a.
- Независимый consumer собирается с изменённым публичным пакетом: [consumer-build.log](consumer-build.log), `BUILD SUCCEEDED`.

Живые значения красного канала центра Day: Large 247–251, Medium 248–251, Small 247–251. Night: все три 13–25. Это доказывает реальное изменение opacity в сцене, не только математическую функцию. Снимки UI не измеряют точную частоту кадров или длительность каждого отображённого кадра; точная кривая подтверждена отдельным тестом общего runtime и прочитанным Figma-контрактом.

## Внешний вид и регрессия зависимости

[Попиксельная проверка](static-regression.json), воспроизводимая `Scripts/compare_button_skeleton.py`: **15/15** ранее принятых Day-поз (2 core keyframe + 13 Text) RGBA-идентичны на исходном @3x без ресайза, сдвигов или нормализации. Оба Night keyframe дополнительно проходят проверку исходного цвета и opacity в нативном XCTest. Изменён только параметр геометрии с прежним default. Проверенные варианты, правила и motion-математика общих компонентов сохранены.

У шести Button static renders после замены прямой заливки вложенным View отличается растеризация по краям: максимальная разница по каналу 5–6/255 в Day и 16–20/255 в Night на @3x. Размеры и центральный цвет прежние. Эти PNG **не объявлены попиксельно идентичными**. Три свежие Day-пары с Figma @1x: MAE 0.008127 Large, 0.005629 Medium, 0.040936 Small; максимальная разница 3/2/2 соответственно. Метод: native @3x → @1x LANCZOS, белый фон, без подгонки. [Сравнительный лист](source-pairs.png) просмотрен визуально.

Проверка позволяет обновить ровно изменённый input hash `TUISkeleton.swift` у уже принятых core/Text после содержательной регрессии, сохраняя исторические доказательства. Новые варианты этих наборов не добавлены и complete вручную не назначается.

Header Large также ссылается на эту зависимость через `TUISkeletonText`. Все 13 default Text-стилей идентичны, расчёт движения не менялся, живой core/Text повторно проверен. Поэтому обновляется только hash Skeleton и ссылка на этот отчёт; Header-specific UI-запуски остаются историческими. Незакрытая повторная приёмка двух примеров Header с TUILink и остальные устаревшие входы не обновляются и не считаются проверенными.

## Что остаётся открытым

Button остаётся in-progress: нужны полные Figma-пары применимой матрицы, отдельная Night source-проверка, решение по legacy/system SF и ресурсам, Glass/backdrop, дополнительные настройки и точная анимация старого вложенного Loader. Этот отчёт закрывает неизвестность Skeleton, а не всю категорию Button motion. Полная библиотека из 112 активных кастомных наборов ещё не принята. 16 системных наборов остаются excluded.
