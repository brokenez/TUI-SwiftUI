# TUI-SwiftUI: индекс текущей работы

Актуальный объём от 9 октября 2026: 112 наборов для переноса и приёмки; [16 системных наборов Apple исключены](excluded-system-components.md). Все 128 исходных наборов остаются в метаданных и паспортах. `inventory.json` разделяет основной список `components` и справочный `excludedSystemComponents`; исключение не означает complete. Системные элементы будущих экранов создаются нативными API iOS 26 напрямую.

Решение пользователя от 8 октября 2026: использовать существующий проект для SwiftUI-библиотеки интерактивных iOS-прототипов; идти через инвентаризацию и спецификации, затем архитектуру, Foundations и первые три базовых компонента. Новый проект и дубликаты реализации не создаются.

Существующий Swift Package импортируется как `TUIDesignSystem`. Запрошенное имя поставки — `TUI-SwiftUI`; способ добавить его без поломки действующего импорта определяется на этапе архитектуры. Каталог уже существует: `TUIDesignSystemCatalog.xcodeproj`. Независимый потребитель: `Examples/ConsumerApp/TUIConsumer.xcodeproj`.

## Инвентаризация

- [Полный машинный индекс](inventory.json): имена, Component Set ID, отдельные Component/variant ID, исходные свойства и состояния, ссылки, зависимости, источники и неизвестные поля.
- [Таблица реализации и проверки](component-status.md): обязательные пять колонок; готовность берётся из действующей приёмки.
- [Порядок этапов](work-plan.md): что сохраняем, что проверяем и критерий перехода к следующему этапу.

Свежий read-only Figma Desktop MCP подтвердил присутствие всех 128 импортированных наборов на странице Components `0:1`. Дополнительно наблюдаются 14 блоков календаря с дочерними symbols. Их Component Set type, публикация, свойства и включение в объём ещё UNVERIFIED. Они сохранены как кандидаты, а не смешаны с действующим реестром приёмки.

На странице Legacy `65645:57406` наблюдается `[legacy] tui-badge [subscription]` `45235:304495`, 180 symbols. Он исключён из основной подборки. Ни один из 128 импортированных set ID на этой странице не найден. Это не доказывает отсутствие других аннотаций Deprecated внутри Components: они ещё требуют проверки контекстов и описаний.

152 импортированных variant ID не наблюдаются в свежем metadata страницы. Не считать их удалёнными: metadata не заменяет get_design_context конкретного набора. Все импортированные строки сохранены, исторические iOS 18 учитываются отдельно.

Проверка опубликованной библиотеки через `list_file_components_for_code_connect` вернула ограничение плана/seat. Публикация наборов — **UNVERIFIED**; тариф и права не менялись. Свежий `get_design_context` потребовал разрешённую папку экспорта ассетов; изменение Allowed directories не выполнено. Эти ограничения не превращают сохранённые описания в принятые спецификации. [Ответы MCP](../Documentation/Inventory/2026-10-08/).

Описание, варианты, свойства и найденная ссылка — факты импорта. Наличие ссылки не подтверждает чтение спецификации. Непринятые правила, bindings, граф зависимостей и недоступные материалы отмечены UNVERIFIED. Частично прочитанные материалы сохранены со ссылками; они не дают компоненту complete.

Определения Variables/стилей прочитаны через свежий MCP отдельно для всех 128 наборов и сохранены с set ID. У payment-logo и sensitive-mode ответ пустой; это не доказывает отсутствия Variables. Ответы содержат наблюдаемые определения, но не полные bindings, alias-цепочки и все режимы тем. Поэтому статус этого поля PARTIAL, без объявления законченной сверки Foundations.

## Обновление индекса

Из корня репозитория:

```sh
python3 Scripts/generate_component_coverage.py
python3 Scripts/generate_inventory_docs.py
python3 Scripts/generate_inventory_docs.py --check
```

Генератор использует действующие исходные реестры и сохранённый MCP-снимок от 8 октября. Он не выполняет повторный запрос Figma и не изменяет ни исходные Figma-файлы, ни статусы приёмки. При новом снимке сначала провести сверку источника; при изменениях реализации обновить доказательства согласно [verification-workflow.md](../Documentation/verification-workflow.md).
