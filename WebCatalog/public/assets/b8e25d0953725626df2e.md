# Loader: чтение спецификации перед реализацией

Реализация в этом этапе не менялась. Сначала изучается полный источник, согласно последнему решению пользователя. Расширенная доступность исключена из работы по [согласованному объёму](../../prototype-acceptance-scope-2026-10-08.md).

## Найденные источники

Импортированный набор Mobile — 9999:26, tui-loader. Его documentationLinks разрешается в [Loader guide](https://www.figma.com/design/Nv37Me0sNdmm3wt0L1j8dF/tui-loader?node-id=6241-1360). Эта ссылка ведёт на Getting Started, а не на сами требования.

Инвентарь MCP показывал только Getting Started. Read-only список фактических страниц обнаружил также Design 0:1 и Local components 6241:1359. По observed ID страницы Design получена структура и прочитаны дочерние фреймы:

- [Варианты 6004:2625](https://www.figma.com/design/Nv37Me0sNdmm3wt0L1j8dF/tui-loader?node-id=6004-2625): Mobile/Desktop, 12, 16, 24, 32, 40.
- [Построение 6082:1102](https://www.figma.com/design/Nv37Me0sNdmm3wt0L1j8dF/tui-loader?node-id=6082-1102): линия по умолчанию 1/12 высоты, минимум 1,5 px; допустим произвольный размер.
- [Кастомизация 6001:19145](https://www.figma.com/design/Nv37Me0sNdmm3wt0L1j8dF/tui-loader?node-id=6001-19145): цвет из палитры или произвольный, изменение размера контейнера и толщины, минимум толщины 1,5 px.
- [Поведение 6001:9192](https://www.figma.com/design/Nv37Me0sNdmm3wt0L1j8dF/tui-loader?node-id=6001-9192): работает неопределённое время; минимальное отображение 500 мс, допускается изменение.

Контексты и контрольные суммы — [reading manifest](../../Inventory/2026-10-08/specification-reading-manifest.json). Отдельные иллюстрации построения/кастомизации ещё требуется просмотреть. Поэтому чтение полной спецификации пока PARTIAL; до его окончания компонент не переписывать.

## Точная анимация в тексте и схеме

Прочитана [схема времени](spec-full-6001-9192-2026-10-08.png): линия заполняется 0 → 95% за 2000 мс, затем уменьшается до 0 за следующие 2000 мс. Контейнер вращается вокруг центра на 360° за 2000 мс. Полный цикл — 4000 мс, easing linear. Извлечённые span/li прочитаны отдельно: одни p-заголовки пропускали параметры линии и контейнера.

Внутри раздела есть ссылка на [прототип Lottielab](https://cdn.lottielab.com/l/CigdXR1yqTGvPN.html). HTML и точный JSON, адрес которого указан в HTML, сохранены рядом. Это исходные файлы прототипа, без добавления runtime-зависимости Lottie.

JSON задаёт 100 fps, 400 кадров (4 с), но расходится с текстом: group rotation 0 → 356° за 400 кадров; trim end 0 → 95% к кадру 201, промежуточный 88,21% на 219, затем 0 на 400; trim offset −342° на 201 → 0 на 400. Таким образом, вращение в прототипе отличается от описанных двух оборотов за четыре секунды. Это реальное противоречие источников, его нельзя скрыть единственным утверждением «как в спецификации».

## Подтверждённые пробелы текущего кода

TUILoader только вращает статический экспортированный контур за 1 с. Нет изменения длины линии по 4-секундному циклу, публичного цвета, произвольного размера и толщины. Это не совпадает с прочитанным контрактом. Исправление выполняется после завершения чтения источников; motion/integration/visual acceptance не присваиваются этим отчётом.

TUIButton использует другое вложенное исходное представление — tui-loader/S/Black, main node 25751:593068, instance 41658:297261. Не переносить правила современного набора 9999:26 на него автоматически: нужно подтвердить связь и применимость. Повторное чтение design context подтверждает Progress Indicator и исходный контур, но не его motion. Обычная адаптивность и анимация нужны независимо от исключённых accessibility-режимов.
